# 快速理解

<!-- papers-manager:section-meta v=1
{"description":"Transformer 用注意力承担序列间的信息交互；概括翻译效果、并行训练优势，以及自回归解码和长序列开销的边界。"}
-->

**核心问题**：能否不用沿词序逐步更新的循环网络，仍然学好输入与输出之间的依赖？

**核心办法**：编码器用 self-attention 汇集源句上下文；解码器一边读取已知译文，
一边通过 cross-attention 查询源句，再预测下一个词。注意力处理跨位置交互，
前馈网络处理各位置的特征变换，位置编码补充顺序信息。
[架构，§3](https://arxiv.org/pdf/1706.03762v7#page=3)

**主要证据**：Table 2 的 big 模型达到英德 28.4、英法 41.8 BLEU；
这不是所有配置都达到的成绩，英法正文另有 41.0 的冲突，见“翻译主结果”。
[Table 2 与 §6.1](https://arxiv.org/pdf/1706.03762v7#page=8)

**使用判断**：关键优势是训练时的位置并行和较短的信息传递路径，不是取消了所有顺序依赖。
原模型生成译文仍然逐词进行，全局注意力也不意味着任意长输入都便宜。
[§3、§4](https://arxiv.org/pdf/1706.03762v7#page=6)

**阅读范围**：本例重点展开架构、训练、翻译实验及模型变体；句法分析任务与附录可视化
未在本例展开，不能据此宣称已经覆盖所有实验或复现细节。

# 方法如何工作

<!-- papers-manager:section-meta v=1
{"description":"从源句与目标前缀到下一词预测，串联缩放点积、多头、三类注意力、位置编码及训练机制；具体细节分子节索引。"}
-->

可以把模型理解为两个相连的计算过程：先把源句编码成可查询的表示，再让目标位置
根据已知译文和源句信息生成预测。下面分别解释信息从哪里来、如何交互，以及训练
怎样保证预测时不会偷看答案。
[Figure 1、§3](https://arxiv.org/pdf/1706.03762v7#page=3)

## 编码器与解码器：输入、输出和信息流

<!-- papers-manager:section-meta v=1
{"description":"说明源句编码、目标前缀解码及 cross-attention 的连接；区分训练时整段目标已知与推理时逐词生成。"}
-->

**输入与输出**

- 编码器接收源语言 token 序列，输出每个源位置的上下文表示；不是把整句压成一个固定向量。
- 解码器接收移位后的目标序列，并查询编码器输出，产生各目标位置的隐藏表示。
- 输出层把隐藏表示映射到词表概率。推理时选择下一个 token，再把它接到前缀上继续生成。

**层内流程**：原始 base 编码器和解码器各有 6 层。编码器每层包含 self-attention
和逐位置前馈网络；解码器还包含读取编码器输出的注意力子层。子层之间使用残差连接，
原论文采用先残差相加、再 LayerNorm 的顺序，不能直接替换成后来常见的 pre-norm。
[§3.1、Figure 1](https://arxiv.org/pdf/1706.03762v7#page=3)

**为什么要分清训练和推理**：训练时参考译文已经给定，可以同时计算多个目标位置的损失，
但必须屏蔽未来 token。推理时下一个 token 尚未知，因此即使没有 RNN，生成依然自回归。
“训练可并行”不能直接推导成“整句可以一次生成”。
[§3、§3.2.3](https://arxiv.org/pdf/1706.03762v7#page=5)

## 缩放点积注意力：如何选择并汇集信息

<!-- papers-manager:section-meta v=1
{"description":"解释 Q/K/V 的不同角色、打分—缩放—归一化—加权过程，以及缩放对 softmax 数值范围的作用；对应公式 (1)。"}
-->

**要解决的子问题**：当前位置需要从哪些位置取信息、各取多少？

- **Query** 表示当前检索需求；**Key** 用于和需求计算匹配程度；**Value** 是被汇集的信息。
- 对一个 Query，与所有允许访问的 Key 做点积，得到一组匹配分数。
- 按 Key 维度的平方根缩放分数，再经过 softmax，得到对这些位置的权重。
- 用权重对 Value 加权求和，得到当前 Query 的输出。多个 Query 可以合并为矩阵计算。

**设计理由**：维度变大时，未经缩放的点积可能有更大的幅度，使 softmax 过于尖锐，
影响梯度。缩放调整的是匹配分数的尺度，不是减少 token 数，也不是把结果直接平均。
原论文给出的分析使用了分量独立、零均值和单位方差的假设，不能把它说成所有训练状态下的严格保证。
[§3.2.1、公式 (1)](https://arxiv.org/pdf/1706.03762v7#page=4)

**阅读解释**：区分 Key 和 Value 有助于理解“按什么找到信息”和“实际取回什么信息”
不是同一个角色；但不能因此断言某个维度固定对应某个人类语义。
公式本体回原文查看，这里不从 PDF 文本碎片重构 LaTeX。

## 多头注意力：不同投影如何互补

<!-- papers-manager:section-meta v=1
{"description":"说明每个头独立学习 Q/K/V 投影、并行聚合后拼接并映射输出；解释固定总宽度下头数与每头容量的取舍。"}
-->

**计算步骤**

1. 每个头用自己的可学习矩阵投影 Q、K、V，而不是重复运行一模一样的注意力。
2. 各头在自己的表示空间中独立计算注意力，得到各自的输出。
3. 将多个头的结果拼接，再用输出投影组合为模型需要的表示宽度。

**base 配置的直观含义**：模型宽度为 512，使用 8 个头，每个头的 Key/Value 维度为 64。
因此多头并不是 8 份完整 512 维注意力直接叠加。论文通过缩小每头维度，使总计算量
与完整宽度的单头方案接近。
[§3.2.2、Figure 2](https://arxiv.org/pdf/1706.03762v7#page=5)

**设计取舍**：多个头允许不同位置和不同表示子空间的信息并存；但在固定总宽度下，
头数越多，每头表达空间越小。因此“更多头一定更好”不是该机制的结论，需结合头数实验判断。
也不要把某个头的可视化行为写成所有输入上稳定、固定的语法分工。
[§3.2.2、Table 3(A)](https://arxiv.org/pdf/1706.03762v7#page=9)

## 三类注意力：谁可以读取谁

<!-- papers-manager:section-meta v=1
{"description":"对齐编码器 self-attention、解码器 masked self-attention 与 cross-attention 的信息来源和访问范围。"}
-->

- **编码器 self-attention**：Q/K/V 都来自编码器侧表示，源位置可以读取整个源句。
- **解码器 masked self-attention**：Q/K/V 都来自解码器侧，但屏蔽未来位置，建立目标前缀内部的依赖。
- **编码器—解码器注意力**：Query 来自解码器侧表示，Key/Value 来自编码器输出，使当前目标位置能够查询源句。

三者共用注意力计算方式，差异在信息来源和访问限制。不能把 cross-attention
描述成“编码器读取解码器”，也不能把编码器的双向访问规则照搬到目标生成端。
[§3.2.3](https://arxiv.org/pdf/1706.03762v7#page=5)

### 目标移位与 causal mask：如何避免答案泄漏

<!-- papers-manager:section-meta v=1
{"description":"解释目标输入右移与未来位置屏蔽如何共同保证下一词预测只依赖已有前缀，避免将并行训练误解为并行生成。"}
-->

预测某个目标 token 时，输入不能已经包含该 token 的答案信息。原模型让目标输入相对
预测目标移位一位，并在注意力 softmax 前屏蔽不允许访问的位置。

- 移位解决“当前位置输入就是待预测答案”的问题。
- mask 阻断经后续位置读取未来答案的路径。
- 训练时仍可一次处理整段已知目标，只是每个位置能访问的信息受限制。

**使用判断**：这是对信息依赖的约束，不是要求程序用循环逐行计算注意力；反过来，
训练时并行计算也不会消除推理时必须等待新 token 的依赖。
[§3.1、§3.2.3](https://arxiv.org/pdf/1706.03762v7#page=3)

## 位置编码与前馈网络：交互之外还需要什么

<!-- papers-manager:section-meta v=1
{"description":"区分位置编码提供顺序信息与 FFN 提供逐位置非线性变换的作用；指出正弦位置编码的长序列外推只是设计动机。"}
-->

**位置编码**：注意力的内容匹配本身不提供 token 的显式位置。模型在编码器和解码器
底部将位置表示加到 embedding 上，用不同频率的正弦/余弦表示位置。
它不是给注意力分数直接加一个“距离越远越小”的固定惩罚。
[§3.5](https://arxiv.org/pdf/1706.03762v7#page=6)

**逐位置前馈网络**：对每个位置应用同一组两层线性变换，中间为 ReLU。
base 的内部维度为 2048，输入输出宽度为 512；同一层内位置间共享参数，层与层之间不共享。
注意力负责跨位置汇集，FFN 负责位置内的非线性特征变换。标题中的“Attention”
不意味着网络只剩注意力运算。
[§3.3](https://arxiv.org/pdf/1706.03762v7#page=5)

**证据边界**：作者以潜在的长度外推能力作为选择固定正弦编码的理由之一；
但 learned position 与 sinusoidal position 的近似得分，并不证明模型能可靠外推到任意长度。
[§3.5、Table 3(E)](https://arxiv.org/pdf/1706.03762v7#page=9)

## 训练与解码：哪些条件属于可复现配置

**训练配方**

- 使用 Adam；学习率先 warmup，再按训练步数的平方根倒数衰减，warmup 为 4000 步。
- base 的 dropout 为 0.1，label smoothing 为 0.1；这两项不是同一种正则化。
- label smoothing 会改变训练目标，因此不能把不同 smoothing 设置下的困惑度改善直接等同于翻译质量改善。

**主结果解码**：base 使用最后 5 个 checkpoint 的参数平均，big 使用最后 20 个；
beam size 为 4，length penalty 为 0.6。参数平均得到一个模型，不应写成多模型预测集成。
Table 3 变体实验不做 checkpoint averaging，不能与 Table 2 不加区分地比较。

## 多头变体：更多头是否一定更好

<!-- papers-manager:section-meta v=1
{"description":"用 Table 3(A) 的受控头数变体解释单头劣势与过多头的退化；限定结论在固定总计算和英德开发集范围。"}
-->

**问题与控制**：改变头数，同时调整每头 Key/Value 维度，以保持计算量；
其余未列出的配置沿用 base。评测是 newstest2013，不是主结果测试集。
[§6.2、Table 3(A)](https://arxiv.org/pdf/1706.03762v7#page=9)

- 单头：24.9 BLEU。
- 8 头 base：25.8 BLEU。
- 16 头：25.8 BLEU。
- 32 头：25.4 BLEU。

**解释**：单头比 8 头低 0.9 BLEU，但进一步增多头数没有持续收益。
这与固定总宽度下“更多独立子空间”和“每头容量变小”的取舍相容。
后一句是机制解释，不是实验直接测得的内部因果过程。

**不能推出**：所有任务上最优头数都是 8，或者增加头数总会提高质量。
Table 3 没有给出这些差异的多随机种子置信区间，因此不要写成统计显著性结论。
[Table 3 与 §6.2](https://arxiv.org/pdf/1706.03762v7#page=9)

## 正则化与位置编码：哪些指标会产生不同判断

<!-- papers-manager:section-meta v=1
{"description":"对比去掉 dropout、去掉 label smoothing 和 learned position 的开发集结果，说明更低 PPL 不必然对应更高 BLEU。"}
-->

**Dropout**：base 为 25.8 BLEU，去掉 dropout 的变体为 24.6。
这个对照说明正则化配方是结果的一部分，不能只复现注意力结构却忽略训练条件。
[Table 3(D)](https://arxiv.org/pdf/1706.03762v7#page=9)

**Label smoothing**：base 的 PPL 为 4.92、BLEU 为 25.8；不使用 smoothing 的变体
PPL 降到 4.67，但 BLEU 降到 25.3。较低的 PPL 与较好的翻译指标在这个对照中并不一致。
这里支持的是指标之间的取舍，不是“PPL 没有用”。
[Table 3(D)、§5.4](https://arxiv.org/pdf/1706.03762v7#page=9)

**位置编码**：learned position 的变体为 25.7 BLEU，sinusoidal base 为 25.8。
在该实验里两者接近。这个对照保留了位置信息，只替换表示方式，不能解释为“不需要位置编码”；
也没有直接检验训练长度以外的可靠外推。
[Table 3(E)、§3.5](https://arxiv.org/pdf/1706.03762v7#page=9)

## 训练成本与并行性：把实测、估算和复杂度分开

**作者报告的训练条件**：使用 8 张 NVIDIA P100；base 训练 100K 步，约 12 小时；

[§5.2](https://arxiv.org/pdf/1706.03762v7#page=7)

**FLOPs 口径**：Table 2 的训练计算成本由时间、GPU 数和估计的持续浮点吞吐推算。
它不是实测电费、显存占用、API 价格或推理吞吐；本例不把该估算换算成今天的实际成本。
[§6.1](https://arxiv.org/pdf/1706.03762v7#page=8)

**机制层面的优势与代价**：self-attention 让位置间可以直接交互，减少序列方向的顺序操作。
但全局配对数量随长度平方增长；Table 1 的层复杂度比较有其维度与长度条件。
“信息路径更短”不能被写成“输入越长越省计算”。
[§4、Table 1](https://arxiv.org/pdf/1706.03762v7#page=6)

**未核验**：本例没有复现训练速度，也没有独立测量不同硬件上的峰值显存或逐词解码延迟。
如果用于实际选型，应另外评估这些约束；本论文的训练时长不能直接回答线上延迟问题。
